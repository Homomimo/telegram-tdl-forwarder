# Telegram 频道转发助手

把频道帖子复制到目标频道。**手动转发会发新帖；自动监听会记住源帖与目标帖的对应关系，之后可以原地更新。** 请只处理你有权读取和转发的内容。

| 你要做什么 | 怎么操作 | 目标频道会发生什么 |
| --- | --- | --- |
| 转发一条原帖或一个相册 | [把原帖或链接发给机器人](#第一次转发) | 发布新帖，不同步之后的编辑 |
| 批量转发历史消息 | [指定同一频道的起止消息 ID](#相册与范围转发) | 仅发布范围内的消息，相册成员逐条发送 |
| 持续同步频道 | [添加监听源](#让新帖和编辑自动同步) | 复制新帖，将受支持的编辑同步到对应目标帖；不扫描历史 |
| 修正已自动复制的帖子 | [使用 `/resync` 或「手动同步」](#手动修正一条已复制的帖子) | 只更新已有目标帖，没有映射就不操作 |

## 快速部署

以下命令在 **Linux 宿主机**执行。Python 3.14 随容器提供，**不需要升级宿主机的 Python**。准备好 [Docker](https://docs.docker.com/engine/install/)、[Compose 插件](https://docs.docker.com/compose/install/) 和 [TDL](https://docs.iyear.me/tdl/zh/getting-started/installation/)。已有部署且原先挂载的是单个 `forward_history.json`？请先看[旧版历史迁移](#旧版历史迁移)，不要直接重建。

**1. 确认工具可用，并登录负责手动转发的 Telegram 账号。** 本项目把宿主机的 `/usr/local/bin/tdl` 和当前用户的 `~/.tdl` 挂进容器；请用同一宿主机用户登录 TDL 和运行 Compose。

```bash
docker compose version
test -f /usr/local/bin/tdl && test -x /usr/local/bin/tdl && echo 'TDL 可执行文件已就绪'
/usr/local/bin/tdl login -T qr
```

**2. 克隆仓库，填写本地配置。** 已有 `.env` 不要覆盖。

```bash
git clone https://github.com/Homomimo/telegram-tdl-forwarder.git
cd telegram-tdl-forwarder
cp -n .env.example .env
chmod 600 .env
nano .env
```

| 配置项 | 填什么 |
| --- | --- |
| `API_ID`、`API_HASH` | 在 [Telegram API development tools](https://my.telegram.org/apps) 获取的应用凭据 |
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) 签发的机器人令牌，不是 `API_HASH` |
| `ADMIN_IDS` | 你本人的 Telegram **用户 ID**；多个管理员用英文逗号分隔 |
| `FORWARD_TO_CHAT_ID` | **目标频道**，例如 `1234567890`，也接受标记形式 `-1001234567890` |
| `SUBMITTER_IDS`（可选） | 允许投稿、但不能管理机器人的其他用户 ID。留空时只有管理员可投稿 |

全文用 `9876543210` 表示**源频道**、`1234567890` 表示**目标频道**。例如源帖链接 `https://t.me/c/9876543210/42` 中，`9876543210` 是源频道裸 ID，`42` 是消息 ID。部署时换成你自己的两个不同频道；源和目标相同会跳过同步。仅做手动转发时，TDL 账号需能读源帖、在目标频道发帖；不用生成 `USER_SESSION_STRING`。其他选项见 [`.env.example`](.env.example)。请勿分享填写后的 `.env`、会话字符串或展开了凭据的 Compose 配置。

**3. 启动并验证。**

```bash
docker compose up -d --build telegram-bot
docker compose logs -f telegram-bot
```

然后用 `ADMIN_IDS` 中的账号私聊机器人：发 `/start` 应看到管理面板，发 `/showto` 应看到你设置的目标频道。

## 第一次转发

1. 私聊机器人，发送 `/showto`，确认这次投稿的目标频道。
2. 转发频道原帖，或粘贴原帖链接，例如 `https://t.me/channel_name/42` 或 `https://t.me/c/9876543210/42`。频道首页、评论和话题链接不能代替原帖；单独上传本地文件也不会入队。
3. 看到「已加入转发队列」后，到目标频道核对。手动转发使用 TDL，没有逐条投递回执时会显示「待核对」，不等于失败。[如何读任务通知](#任务通知与查询结果)

### 相册与范围转发

假设同一源相册有三张图，消息 ID 分别是 `100`、`101`、`102`：

| 操作 | 目标频道收到什么 |
| --- | --- |
| 直接发 `https://t.me/c/9876543210/101` | 按原相册整组转发 |
| 直接发 `https://t.me/c/9876543210/101?single` | 只发第 `101` 条 |
| 发 `/export_range 9876543210 100 101` | 第 `100`、`101` 条各自独立发送，不带上 `102` |
| 发 `/export_range 9876543210 100 102` | 三条都发，但不会重新组成相册 |

**范围转发按消息 ID 选取，包含两端。** 在面板点「批量转发」也一样：依次回复同一源频道的起止原帖链接，核对目标和范围后再确认。端点链接有没有 `?single` 不改变范围，也不改变发送方式。范围可包含文字和媒体，不用于修正已发布的帖子。

## 自动监听与手动同步

### 让新帖和编辑自动同步

1. 在 `.env` 设置 `MONITOR_CHAT_IDS=9876543210`。监听源只填裸 ID，不加 `-100`；多个源用英文逗号分隔。
2. 若使用用户账号监听，先让该账号加入源频道，并赋予它在目标频道发帖及编辑对应帖子的权限。然后运行 `docker compose run --rm gen-session`，按提示登录，将输出的 `USER_SESSION_STRING=...` 填回 `.env`，保持 `USER_MONITOR_ENABLED=1`。**这个字符串等同于登录凭据。**
3. 运行 `docker compose up -d --force-recreate telegram-bot` 载入配置。发 `/monitor` 核对源频道，再发一条测试源帖：先确认它被自动复制，再修改说明，检查**同一条目标帖**是否更新。

只用 Bot 时，它必须能收到源频道更新并有权在目标频道发帖、编辑。Bot 和用户账号都在线时，程序按源频道、源消息 ID 和目标频道去重；复制优先用收到更新的账号，编辑优先用原发送账号。两者都没收到的更新不会从历史补齐。

<details>
<summary>什么时候会使用 TDL 回退？需要哪些权限？</summary>

**普通权限不足不会触发 TDL 回退。** 只有自动复制新帖明确收到 `CHAT_FORWARDS_RESTRICTED` 时才检查 `MONITOR_TDL_FALLBACK`。Compose 中该变量留空或未设置时默认开启，直接运行 Python 时默认关闭；显式设为 `0` 均关闭。启动日志显示实际开关。

关闭时，这次复制报告失败；开启时，由 TDL 下载媒体、当前监听账号上传发送，再用 Telegram 回执把源帖对应到目标消息 ID。若遇到的是明确的发帖或访问权限拒绝，程序可改用另一在线监听账号的权限尝试一次；结果不明时不会换号重发，编辑失败也不会另发新帖。

- **权限分工：** TDL 登录账号需要能读取和下载源媒体；实际发送和后续编辑由 Bot 或用户监听账号执行，该监听账号需要源频道读取和目标频道发帖、编辑权限。TDL 和监听账号不必是同一个账号，但不会借用彼此的频道访问凭据。
- **照片上传：** 普通照片按 JPEG 上传；作为文件发送的图片、视频仍按文档处理。源频道或照片启用内容保护时，只有当前监听账号被 Telegram 确认为源频道所有者才处理照片上传；无法核实权限时，不发布相册，也不替换目标照片。
- **相册不逐条拆发：** 按真实 `grouped_id` 核对源成员，按源消息顺序通过一次相册请求发送，并分别记录各成员映射。每个成员保留自己的说明、文字格式和媒体剧透标记；下载、大小校验或上传准备失败时，不发布残缺相册，也不降级成纯文字。
- **保守处理：** 相册已有投递或待核对成员时，不整组重发，也不把剩余成员拆开发送；回执缺失时只保存确认的映射，其余列为待核对，不自动重发。旧版 TDL `clone` 已发送的消息仍只有去重记录，不会追猜目标 ID 或自动补建映射。
- **运行开销：** 回退和媒体替换需要临时磁盘空间及下载、上传流量；临时文件在任务结束或取消后删除。Telegram 对文件大小、媒体格式和编辑权限的限制仍然适用。

</details>

### 手动修正一条已复制的帖子

在管理员私聊发送 `/resync https://t.me/c/9876543210/42` 或 `/resync 9876543210 42`。如果用面板，点「手动同步」后，**回复机器人刚发的输入提示**，粘贴源帖链接。不要另发一条独立消息，否则会走普通转发，可能多发一份。

请使用当前监听源的 `t.me/c/频道裸ID/消息ID` 原帖链接，不是目标帖链接、公开用户名链接、评论或话题链接。源帖与目标帖必须已有映射；手动转发和范围转发不会建立映射。

### 任务通知与查询结果

| 看到什么 | 表示什么 | 接下来怎么做 |
| --- | --- | --- |
| 待确认 | 面板已生成预览，任务还没执行 | 核对目标和范围，再点「确认执行」 |
| 已入队 | 任务已保存，不代表目标帖已发布或更新 | 等待执行；用 `/queue` 查看队列。同步通知中的目标帖链接不是完成凭据 |
| 自动复制成功 / TDL 回退上传成功 | 已取得目标消息 ID 并保存映射 | 点通知中的目标帖链接查看；已知相册成员的链接带 `?single` |
| 部分消息已确认，其余待核对 | 已确认成员有目标帖链接，其余只列源消息 ID | 对照未确认的 ID 查看目标频道，不要整组重发 |
| 投递结果待核对 | 可能已经送达。手动 TDL 命令正常退出或发送阶段超时，都不能据此认定成功或失败 | 查看 `/queue` 中的任务及 `/flog` 转发记录，再去目标频道核对；程序不会自动重发 |
| 当前目标没有转发映射 | `/resync` 没有可更新的目标帖，没有补发 | 确认用的是源帖、目标频道未切换；旧映射也可能已过期 |

`/queue` 看排队和待核对事项，`/flog` 看近 7 天内最新的 10 条转发记录；排查启动、登录或存储异常才看容器日志。这三者不是同一份记录。

**想长期同步旧帖？** 默认每 7 天清理一次已确认满 7 天的映射。可提前在 `.env` 调整 `MONITOR_MAP_RETENTION_DAYS`（`0` 为永久保留），并重新创建容器。清理不会删除频道帖子，但之后无法用 `/resync` 定位旧目标；改设置也不会还原已清理的映射。

## 命令速查

| 用途 | 命令 |
| --- | --- |
| 打开管理面板 / 分步向导 | `/start` · `/help` |
| 查看 / 切换目标 | `/showto` · `/forwardto 1234567890` |
| 查看 / 增删监听源 | `/monitor` · `/monitor add 9876543210` · `/monitor del 9876543210` |
| 替换 / 清空监听列表 | `/monitor set <源ID1,源ID2>` · `/monitor clear` |
| 原地同步已映射的帖子 | `/resync 9876543210 42` |
| 批量转发历史范围（含两端） | `/export_range 9876543210 100 200` |
| 查看队列 / 停止手动任务 | `/queue`（按提示用 `/queue <任务 ID>` 查看更早的待核对记录）· `/tdlstop` |
| 最近 10 条转发记录 / 清空本地记录 | `/flog` · `/flog clear` |
| 重启机器人进程 | `/restart` |

- **设置生效范围：** `/forwardto` 和 `/monitor` 修改的是当前进程配置。要跨重启保留，请修改 `.env` 并重新创建容器。切换目标不影响已入队任务。
- **停止与清理：** `/tdlstop` 停止当前手动 TDL 任务，清空等待任务及定时重试；不会强停正在执行的自动同步，也不会撤回帖子。`/flog clear` 只清转发历史，不清映射或待核对任务。
- **按钮如何回复：** 回复机器人的输入提示，而不是另发消息。输入提示和确认页 5 分钟有效；回复「取消」可退出，重新打开 `/start` 或 `/help` 会使旧面板失效。请直接发送管理命令，不要转发命令消息。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| `PHOTO_EXT_INVALID` / `The extension of the photo is invalid` | 旧版把普通照片命名为 `.bin`。更新并重建容器后，照片会用 `.jpg` 上传。如果仍然报错，请按日志中的源消息 ID 核对；此错误发生在发布或编辑之前，不必清空映射库。`/resync` 只适用于已有目标帖的情况。 |
| 手动转发正常，自动监听却没有新帖 | 用 `/monitor`、`/showto` 核对源和目标；确认 Bot 或用户监听账号确实收到了更新并有发帖权限。若提示“频道实体尚未就绪”，任务已保留，重启或同源新更新会再次尝试。若提示“未能持久化”，按告警中的消息 ID 核对，并检查数据卷空间和写入权限。 |
| 文字更新了，但附件没有更换 | 原地替换支持照片、视频以及以文件形式发送的普通图片和视频；其他附件只同步文字。相册按成员更新。若 Telegram 拒绝替换，不会删除原帖重发 |
| 目标帖还在，手动同步却提示没有映射 | 确认提交的是**源帖**，且目标频道未切换。手动 TDL 转发不建立映射；映射过期或数据卷被删除也会导致这种情况 |
| 更改 `.env` 后仍提示 Token 无效 | 核对 `BOT_TOKEN` 是否为 BotFather 签发的有效令牌，然后执行 `docker compose up -d --force-recreate telegram-bot`。仅 `restart` 不会重新载入 `.env` |
| 日志提示转发历史损坏 | 在 `./history/` 查找程序保留的 `.corrupt-*` 备份，先核对再处理。转发历史与同步映射是两份数据，不要为修复历史而删除 `monitor-data` |

## 运维与数据

### 数据存放位置

以下是仓库自带 Compose 的默认挂载。`./history` 是宿主机目录，**`monitor-data` 是 Docker 命名卷，不是仓库里的同名文件夹**。

| 数据 | 宿主机位置 | 容器内位置 |
| --- | --- | --- |
| 转发历史（`/flog`） | `./history/forward_history.json` | `/data/history/forward_history.json` |
| 源帖与目标帖的映射、复制去重记录 | `monitor-data` 卷 | `/data/monitor/message_map.sqlite3` |
| 等待、重试及待核对任务（`/queue`） | 同一个 `monitor-data` 卷 | `/data/monitor/message_map.sqlite3.queue.sqlite3` |
| TDL 登录会话 | 运行 Compose 的用户的 `~/.tdl` | `/root/.tdl` |

要找 `monitor-data` 在这台 **Docker 宿主机**上的实际位置，创建容器后执行下列只读命令。它只显示挂载到 `/data/monitor` 的卷名和路径，不会输出环境变量：

```bash
docker inspect --format '{{range .Mounts}}{{if eq .Destination "/data/monitor"}}{{.Name}} → {{.Source}}{{end}}{{end}}' telegram-tdl-forwarder
```

**停服、更新与备份：** 日常停服用 `docker compose down`，不要加 `-v`，否则会删除命名卷。备份时先停服务，一并保留 `./history/` 和整个 `monitor-data` 卷，不要只留映射库而漏掉队列库。更新代码后用 `docker compose up -d --build telegram-bot` 重建；查看日志用 `docker compose logs --tail=100 telegram-bot`。

<details>
<summary>相册、重试与临时消息的处理规则</summary>

- 自动监听从首个相册成员起收集更新；1 秒仅是初次收集窗口，到期不表示会发送。不会因为只收到单条更新就拆发。
- 自动相册转发要求收到多成员 `Album` 事件，且该事件包含全部已观察成员、与按 `grouped_id` 回读的结果一致。只有单条更新、两种来源不一致或回退下载期间发现更多成员时，先等待而不是发送局部。等待任务保存在队列中，收到同组事件可再核对；缺少相册事件的旧任务可由管理员核对源帖后手动补发。`Album` 事件本身由客户端聚合，并非服务端提供的成员总数，不能保证识别所有异常分批。已投递过部分成员时不会拆发余下成员。
- TDL 回退额外查询已知成员前后各 100 个消息 ID，只选择源频道中实际具有相同 `grouped_id` 的成员；不是把连续 ID 当作成员。成员触及边界、缺少已观察到的成员、少于 2 条或多于 10 条时拒绝发送，异常大跨度或无法核对的相册需要人工检查，不能保证任意异常分布均可补齐。
- 同一帖子反复编辑时合并排队；明确限流后保留重试时间，重启不会丢掉最新修改。若上次编辑中断或回执不明，会先比较源帖和**已映射的目标帖**，只更新有差异的内容，不另发新帖。回退上传的媒体按目标媒体指纹核验；旧记录缺少可验证的指纹时保留为待核对，不以说明文字相同代替媒体核验。已清理映射的旧帖不占用等待回执的编辑名额。
- 自动入队遇到存储故障最多再试两次；仍失败则合并通知管理员，列出源消息 ID。复制回执先落库，再发送状态通知；即使通知时停服，已确认成员也不列入 `/queue` 的待核对项。
- 自动复制收到明确的发送限流时，运行中的重试沿用原账号和原请求；等待期间停机，重启后转为待核对，不换号重发。若在发送前遇到映射库锁，最多退避重试两次；仍被锁的任务会保留，解锁后重启可恢复。
- 每条 TDL 子命令默认最多运行 7200 秒，可通过 `TDL_TIMEOUT_SECONDS` 修改（`0` 不限时）。若 Telegram 可能已收到请求但缺少回执，不要为了重试手动删除去重记录。
- 默认在任务结束后清理机器人状态消息：普通状态 300 秒、错误状态 600 秒，普通命令回复 120 秒。管理员的启动面板和帮助保留。
- **按钮消息清理：** 输入提示被回复、取消或被新面板替代后保留 30 秒；未回复则在 5 分钟有效期结束后清理。独立确认卡过期时优先恢复原面板再删除；确认或取消后，已变为当前面板的卡片保留到被新面板替代。普通命令回复默认 120 秒、错误或过期提醒 600 秒；带目标帖链接的按钮同步入队通知默认保留（`AUTO_DELETE_SYNC_RECEIPT_SECONDS=0`，正数为保留秒数）。只清理机器人自己的消息，不删除你的输入或目标频道帖子。定时清理不跨进程重启。可在 `.env` 设置 `AUTO_DELETE_BOT_MESSAGES=0` 关闭自动删除，或通过 [`.env.example`](.env.example) 分别调整时长。

</details>

### 旧版历史迁移

仅适用于以前把 `./forward_history.json` **作为单个文件挂载**的部署。在原 Compose 项目目录执行；如果目标文件已经存在，请先人工核对，不要覆盖。保留原文件以及 `monitor-data` 卷。

```bash
docker compose stop telegram-bot
mkdir -p history
if [ -f forward_history.json ] && [ ! -e history/forward_history.json ]; then
  cp -p forward_history.json history/forward_history.json
fi
docker compose up -d --build telegram-bot
```

旧 Compose 中如有明文凭据，先迁到本地 `.env`。若凭据曾进入公开仓库或共享镜像，请轮换 Bot Token，并撤销已暴露的用户会话。

### 离线测试

运行时版本以 [Dockerfile](Dockerfile) 和 [requirements.txt](requirements.txt) 为准。以下任选一种方式运行测试；安装依赖或首次构建需要联网，执行测试不需要 Telegram 凭据。

**本地 Python 3.14**（在 Linux 仓库根目录创建虚拟环境）：

```bash
python3.14 -m venv ~/.venvs/tdl-forwarder
. ~/.venvs/tdl-forwarder/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

**仅使用 Docker**（在 Linux 仓库根目录执行）：只挂载测试目录，测试容器禁用网络，不读取 `.env` 或生产数据卷。

```bash
docker build --pull -t tdl-forwarder:test .
docker run --rm --network none -v "$PWD/tests:/app/tests:ro" tdl-forwarder:test python -B -m unittest discover -s tests -v
```

升级后先在测试频道验证三件事：管理面板按钮能响应；两张图片能作为一个相册自动复制；修改其中一张的说明后，只更新对应的目标帖，不新增帖子。
